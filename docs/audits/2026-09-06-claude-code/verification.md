## Изолированные воспроизведения

Никакие реальные записи, API модели, пользовательский конфиг и установленное приложение не использовались. Вспомогательные типы — заглушки; ограничения каждого примера указаны ниже. Это дополнительные диагностические проверки, не добавленные в основную test suite.

### AnalyticsSink

`queue-repro.swift` компилировался вместе с настоящим `Sources/amanu/Analytics/AnalyticsSink.swift` и заглушками каталога/настроек/identity. Транспорт локальный, без сети.

1. Старт с выключенной аналитикой → включение → Config.didChange → запись события: bufferedCount=0 вместо 1. start() возвращается до watchTheSwitch().
2. 500 событий → заблокированная отправка → добавление события 501 → успех старой отправки: новое событие не было в отправленном пакете, но очередь становится пустой. trim() сдвигает pending, а завершение запроса удаляет первые count элементов по позиции.

Оба механизма уже присутствовали в Claude-атрибутированном коммите 7c6cb92 от 2026-08-22 и вошли в master в e3d900b. Их нельзя честно считать впервые написанными Codex.

### Локальная транскрипция

`pertrack-repro.swift` содержит точную копию transcribePerTrack из HEAD, с единственным изменением private visibility, и синтетические типы сессии. Компилировался с настоящим TranscriptionEngine.swift. Обе дорожки существуют; fake engine успешно готовится, но transcribe() бросает DecoderFailure на каждой.

Результат: метод возвращает успех с 0 сегментов. Следующий шаг настоящего transcribe() в строках 361–387 сохраняет Transcript и вызывает TrackCompressor.settle. При keep_audio=false (default) это ведёт к discard. Само удаление через полный coordinator в этом примере не запускалось: оно подтверждено чтением цепочки вызовов. Частичный успех также не защищает исходник нераспознанной дорожки.

catch/continue унаследованы из Quill, commit 0d294bc (2026-07-25), ещё до Codex-периода.

### CLI для саммари

`llm-timeout-repro.swift` содержит точную копию LLMBackend.run из HEAD, кроме private visibility, и заглушку ошибки. Вместо модели запущен /bin/sleep 15, который не читает stdin. На вход подан 1 MiB синтетического текста, timeout=0.2s.

Через 2 секунды процесс всё ещё заблокирован на записи stdin: таймер планируется ниже этой записи. Внешний supervisor остановил только созданную им process group. Это проверка поведения subprocess helper; реальные Claude/Codex backends и модельные вызовы не запускались.

## Не проверено вживую

Права TCC на чистом Mac, login item после logout/login, полный цикл DMG → /Applications → первая запись, Intel hardware, реальный звук/route changes, облачные ответы и сервер SQL. Зелёные unit tests не подтверждают эти сценарии.

## Дополнительная проверка находок Claude

### EchoFilter — подтверждено синтетически

`echo-repro.swift` компилируется с настоящим EchoFilter.swift. 25 локальных реплик одной метки me A: 21 короткое «да» и четыре содержательных возражения. Все перекрываются с дальней стороной, содержащей «да». Фильтр удалил все 25 локальных реплик, включая четыре содержательных, слов которых нет на дальней стороне. Ожидалось сохранение этих четырёх. Частота такого сценария при реальной диаризации AssemblyAI не измерена. Механизм классификации echoSpeakers введён в 8835234.

### Релиз из чистого checkout

Точное присваивание SPARKLE_BIN с `set -euo pipefail` выполнено в пустом временном каталоге. Результат exit=1, до маркера сборки выполнение не дошло. Вывод Claude о падении именно на стадии 7 неверен для отсутствующего каталога: shell останавливается немедленно из-за exit status find. Сам дефект порядка инициализации подтверждён.

### Лицензии Sparkle — ложное срабатывание Claude

В `.build/Amanu.app/Contents/Resources/Licenses/Sparkle-LICENSE` уже есть EXTERNAL LICENSES, bsdiff/bspatch (строки 31–55) и sais (59–85). Они есть и в исходном .build/checkouts/Sparkle/LICENSE, который Makefile копирует целиком. Предложение добавлять их как отсутствующие не обосновано.

### Отказы и уточнения

- Запрет микрофона: последовательность Doctor.fail → setupPending=false → ExitCode(1) подтверждена чтением Amanu.swift и SetupWindow.finish; реальная TCC-настройка не менялась. Оценка Codex — P1, а не P0.
- `amanu analytics off`: sink слушает только внутрипроцессный NotificationCenter; Config.update другого процесса его не будит. start/send/record не перечитывают config сами. Цепочка подтверждена кодом; реальная настройка пользователя не менялась.
- `keep_audio=false` означает удаление после успешного транскрипта. Совет Claude вызывать settle при отключённой транскрипции отвергнут: он удалит единственную копию встречи. Нужна архивация с сохранением аудио.
- Добавление EchoFilter в mixed-путь само по себе не исправляет ошибочную атрибуцию сторон: там нет двух независимых расшифровок, по которым фильтр узнаёт дубликат.
- Непрерывное подавление автозаписи после ручного stop — явное решение 0e71efa и тест manualStopDoesNotExpireDuringCall. Не предлагается отменять его по результатам этого аудита.
