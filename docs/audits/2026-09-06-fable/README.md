# Аудит Fable и исправления Amanu

2026-09-06. Исходная точка: `b5e8a77`, кандидатный период Codex — `ad2dd69..HEAD`, 27 коммитов. Принадлежность каждой правки агенту по git не доказуема; часть аналитики импортирована из прежней Claude-ветки.

## Какая модель действительно работала

Запущены три прохода локального Claude Code с `--model fable --effort max`. Аналитика/установка и релиз/тесты полностью выполнены **claude-fable-5**. Проход записи начат Fable, затем Claude Code автоматически переключил его на **claude-opus-4-8** после внутреннего срабатывания `cyber`. Это смешанный проход, несмотря на заголовок его исходного отчёта. Мы не меняли защитные настройки для обхода переключения. Подтверждение из служебных событий CLI: [provenance.json](provenance.json).

Исходные отчёты сохранены без редакторских исправлений:

- [Аналитика, приватность, установка и lifecycle — Fable](analytics-install.md).
- [Релиз, инфраструктура, документация и тесты — Fable](release-tests.md).
- [Запись и обработка — Fable → Opus 4.8](recording.md).

Ревьюеры читали текущий код и историю; производственные исходники оставались неизменными до завершения всех трёх проходов. Во время аудита Codex добавлял регрессионные тесты. Аналитический ревьюер их намеренно не читал; релизный увидел часть новых тестов и позднее обратился к прежнему отчёту. Поэтому нельзя считать три результата полностью слепыми исследованиями. Ревьюеры не запускали тесты и не проверяли реальные устройства или серверы.

## Что не принято буквально и что остаётся

- Рекомендация смешанного аудита «пропускать нечитаемую дорожку в encodeStereo» **не применена**. Helper используется также при архивации с удалением исходников: такой совет может стереть единственную повреждённую, но восстанавливаемую дорожку. Сохранность исходников важнее автоматического объявления неполной встречи успешно обработанной. Для полезной частичной расшифровки потребуется отдельный статус/артефакт, который не разрешает удаление аудио.
- Заключение смешанного аудита о безопасности per-track `catch/continue` опровергнуто выполняемыми тестами. Это одна из причин не принимать рекомендацию «Go» как доказательство готовности.
- Формулировка аудиторов «SPARKLE_BIN падает на стадии 7» неточна: чистый checkout завершался раньше, без сообщения, из-за `set -euo pipefail`. Новая проверка воспроизводит именно ранний отказ.
- Лицензии bsdiff/sais уже входят в полный Sparkle LICENSE; дописывать отсутствующие файлы не требовалось. Ручное подавление автостарта до конца звонка сохранено как намеренное поведение.
- Меньшие ошибки точности телеметрии пока остаются: общий pending-store у нескольких процессов может давать дубли/потери, CLI recovery не всегда считает session_interrupted, выбракованная авто-запись даёт finished и discarded. Они не затрагивают содержимое встреч; межпроцессная очередь требует отдельного изменения протокола хранения, а не одного flock вокруг записи устаревшего массива.
- Четырёхсекундный single-instance handshake сохранён: без проверки гонки одновременного запуска его сокращение может разрешить две записи сразу. Медленные backend probes с критического пути уже убраны.
- Не менялись опубликованные release assets/старые appcast и historical notes. Оговорка об отсутствии физического Intel-теста закреплена для следующих notes. Мелкие замечания к форматированию notes-to-html и серверному дайджесту оставлены вне исправлений перед запуском.
- Production retention, реальная схема Umami, PRIVATE_MODE, systemd timers и серверные логи требуют проверки на сервере. Аудит их состояния не проводился; локальный SQL fixture не доказывает соответствие работающей БД.

## Итог проверки

- До исправлений новые регрессионные тесты воспроизвели ошибки эхо, setup, consent, переполнения очереди, произвольных полей, частичного/пустого transcript и preflight чистого checkout.
- После исправлений: **364 Swift-теста в 44 suites прошли**; **9 Python-тестов прошли**; все проверки лендинга и `bash -n scripts/release.sh` прошли.
- Оптимизированная сборка для arm64 и x86_64 проверена; `lipo -archs` подтвердил оба слайса. CLI `--help` прошёл с `DYLD_FRAMEWORK_PATH`, указывающим на SPM-артефакт Sparkle. Прямой запуск небандлированного release-бинарника без этого пути ожидаемо не находит Sparkle; распространяемый Makefile-бандл кладёт framework в Contents/Frameworks.
- Логи воспроизведений и сборки находятся локально в `.build/audit-fable-2026-09-06/`; исходные публичные отчёты — рядом с этим документом.

Перед широкой раздачей остаётся ручной smoke-test подписанного приложения: установка из DMG, отказ/возврат TCC, выход во время записи, звонок через колонки и гарнитуру, смена устройства, проверка обоих голосов, login item после повторного входа. Физический Intel и минимальная macOS 15 не проверены. Эти ограничения нельзя устранить зелёной компиляцией.

Изменения находятся в рабочем дереве. Коммиты, установка новой версии, подпись, нотаризация и публикация в этом задании не выполнялись.
